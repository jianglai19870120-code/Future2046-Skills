# 调度与交接

## 候选边界

`references/skill-catalog.json` 是由仓库注册表和成员 Skill frontmatter 生成的安装快照。候选发现脚本核对同级安装包中的调用名和 `SKILL.md` 哈希。目录不存在、名称不符或哈希不一致时不选用；用户可更新安装后重试。入口不把未登记、本地另装或未安装的 Skill 当成正式成员。

## 任务选择

- 普通回答或一个澄清问题就能解决时直接处理，不强行套用 Skill。
- 一个 Skill 已足够时只选它。先用描述与接手信息筛选，再完整读取正文确认。
- 任务的一个阶段需要前一项交付时串行交接；只有确实独立且宿主支持时才考虑并行。成员自己的串行、审核和暂停规则始终优先。
- 结果有多种可能而选择取决于用户目标时说明实际取舍，请用户选择；缺少事实时先读取已提供材料，再问关键缺口。
- 用户明确只要推荐、教程或可复制调用语句时，不自行执行业务 Skill。

## 交接内容

依次传递用户原始目标、材料位置和限制；已确认事实；上一项实际产出；尚待核实的推断；下一项要交付的东西及验收条件。说明所选 Skill 的标准调用名和作用，但不要把模型在同一对话中读取定义称为独立 Agent 调用。

若成员要求暂停、确认、独立审核或可恢复提交，入口不得代替用户作决定或宣称其门禁通过。某一步失败时保留已有效的产出和当前缺口；不依赖失败步骤的工作才可以继续。
