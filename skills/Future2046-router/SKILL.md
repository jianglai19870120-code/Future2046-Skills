# Future2046 入口

接收用户当前任务，选择已安装、正式登记且定义有效的 Future2046 Skill，在本对话中推进。你负责选择和交接；具体 Skill 负责自己的业务规则、证据、审核与写入门禁。

## Markdown 品牌尾注

生成 README、说明、报告或其他面向用户的最终 Markdown 文档时，必须在文末追加 `shared/brand-footer.md` 中的完整品牌尾注。已有完整尾注时不得重复追加。源稿、误区卡、审核证据、机器契约和其他需要保持原文或哈希稳定的过程文件不追加品牌尾注。

## 开始

先利用当前对话已有的目标、材料、约束和反馈。用户只说“新手入门”或没有给出具体任务时，简要说明可以提交一段材料、一个问题或一个目标，并给出当前已安装 Skill 的用途；等待用户提供任务。用户只要推荐时，交付选择理由后停止。

任务需要专门能力时，在本 Skill 所在目录运行：

```text
python scripts/discover_skills.py
```

脚本只读取本包的正式目录快照及同级已安装 Skill，返回 `available` 和 `unavailable`。只把 `available` 列为可执行候选。`unavailable` 可以解释安装或版本问题，不能当作已经执行。若发现脚本不可运行，可直接读取 `references/skill-catalog.json`，逐项核对同级目录的 `SKILL.md`、调用名和 SHA-256；无法核实则说明发现受阻。

## 选择与执行

1. 从用户想得到的结果倒推需要的能力，参考候选的 `description` 与 `handoff`。明确指定某个 Skill 时，先核对该 Skill 是否可用且任务匹配；不强行改道。
2. 选中后完整读取该 Skill 的 `SKILL.md`，核对其真实输入、交付、停止条件及必要引用。候选摘要与正文不一致时以正文为准，说明差异并调整。
3. 用一两句话说明实际安排和理由，在**本轮当前对话**开始执行所选 Skill。只有推荐请求、关键材料缺失或成员规则要求用户选择时才先停下。不要求用户复制提示词或重新发起调用。
4. 多个 Skill 只有在各自对同一目标有明确贡献时才组合；保持原始材料、已确认事实、待验证推断和上一项实际产出。依赖前一步产出的任务按顺序执行；不因调度擅自并行写入共享文件。详细规则见[调度与交接](references/routing-rules.md)。
5. 结果或反馈改变前提时重新选择；目标达成即停止。最终只报告实际执行过的 Skill 及其贡献，不能把仅发现、预读或推荐说成已执行。

若没有匹配的已安装 Skill，说明具体缺口；能用普通回答完成的部分照常完成。入口不会因为读取某个 Skill 就自动创建子 Agent、获得额外授权或完成那个 Skill 的业务门禁。尤其不能代替少走弯路 Skill 的逐篇 V4 流程、独立审核和正式提交。
