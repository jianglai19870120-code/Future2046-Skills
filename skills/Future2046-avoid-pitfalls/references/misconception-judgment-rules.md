## 判断边界

误区识别只依据原文内部证据，不引入外部事实核查。必须先完成候选判定，再生成误区观点、口播稿和卡片；不得先写卡片，再倒推误区理由。

## 候选识别顺序

对校正后的全文按以下顺序处理：

```text
识别人物、场景、行为和判断
→ 还原犯错者当时相信什么
→ 查找问题、反转、结果或纠偏
→ 执行五道判定门槛
→ 合并重复候选
→ 生成卡片
```

每个候选必须回答：

1. 谁在什么场景下犯错？
2. 他相信了什么，或者采取了什么做法？
3. 原文为什么能证明这是一种误区？
4. 它能否脱离其他候选独立成立？
5. 它是否和其他候选重复？

## 全文穷举门禁

每篇文稿必须完整扫描校正后的所有语义段落、主题切换和人物决策，再形成候选清单。不得发现第一条合格误区后停止，也不得为了快速落盘只选一条。候选产物必须记录：

```json
{
  "candidateCoverage": {
    "exhaustiveScan": true,
    "reviewedSegments": ["p1", "p2", "p3"],
    "themesReviewed": ["主题A", "主题B"],
    "noMoreCandidatesConfirmed": true,
    "rejectedOrMergedCount": 2
  }
}
```

`reviewedSegments` 必须覆盖全文；`noMoreCandidatesConfirmed` 表示其余段落已经检查，并记录了淘汰、合并或不成立理由。缺少全文覆盖证据时，候选阶段不得通过。

## 五道判定门槛

只有五项全部通过，才允许生成卡片：

1. **错误对象明确**：能指出具体的犯错者、行为主体或决策主体，不能只写“很多人容易犯错”。
2. **错误内容明确**：能还原为明确的错误认知、错误做法或错误判断，不能只停留在主题、情绪或负面评价。
3. **错误场景明确**：能说明错误发生的具体处境、任务或决策阶段。
4. **原文内部纠偏证据存在**：至少出现前后认知变化、错误做法导致问题、原文明确指出局限、判断与结果不一致、相反方向或正误对比中的一种。
5. **可以独立成卡**：不依赖另一候选才能成立，且不是同一错误的重复表达。

## 立场识别

识别候选前，判断原文是在：

- 认同某个观点；
- 反驳某个观点；
- 转述他人观点；
- 展示人物过去的错误认知；
- 展示人物已经改变后的正确认知。

单纯引用他人观点，且无法确认作者或叙述者是否认同时，不得直接拆成误区。出现“过去相信—后来发现不对”的变化时，应优先把过去相信的内容识别为误区，而不是把后来的纠偏结论写成误区观点。

## 证据角色

内部证据分为三类：

- **认知证据**：证明犯错者当时相信什么；
- **问题证据**：证明这种认知或做法出现了什么局限、问题或失败；
- **纠偏证据**：证明原文最终转向了什么方向。

卡片的“原文依据”必须直接覆盖认知证据和问题证据，必要时再补充纠偏证据。口播中新增的案例、人物处境、数字、细节或表达性结论不能作为误区成立依据。

## 应该生成

- 明确的错误认知；
- 明确的错误做法；
- 明确的错误判断；
- 可以独立表达且能被具体场景说明的错误。

## 误区观点规则

本节只保留判断层面的最低要求。观点的语义充分性、原文贴近度、24 字上限、句式标点和原文依据的连续上下文，统一以[误区观点与原文依据规则](viewpoint-and-evidence-rules.md)为准；生成和审核时必须读取该文件，不能用本节的简短说明替代。

- 必须是一句话；
- 不超过 24 个汉字；
- 使用自然、口语化表达，不为了短而写成标签或金句；
- 直接表达犯错者相信的核心错误；
- 写“他以为是什么”，不写“正确答案是什么”；
- 不得写成纠偏后的结论、正确做法或风险提醒；
- 可以使用否定句，只要否定的是犯错者相信的错误判断；
- 不包含后果、解释、纠偏或多个并列错误；
- 不写成关键词、标签或模糊评价。

观点句式必须根据具体错误关系选择，不能机械让所有卡片都使用“以为……”。可在下列结构中选择最贴合的一种，并记录 `viewpointPattern` 与 `patternSelectionReason`：

```text
把 A 当成 B       —— 把手段、表象或短期结果误当成真正结果
以为 A 就能 B     —— 把一个动作直接当成必然结果
只要 A 就会 B     —— 把条件误当成必然充分条件
A 本身就等于 B    —— 把两个概念直接等同
做了 A 就不需要 B —— 以一个动作替代另一个必要动作
把短期结果当长期方法
否定性错误判断
条件错配判断
因果倒置判断
主体归因错误
```

句式选择是为了准确还原错误关系，不是为了表面多样化。比如“很多人以为跨过低谷期靠盲目努力”表达的是把单一努力当成跨过低谷的充分条件，不能机械摘抄原文的一句自我宣言；只有原文同时提供相应行为、限制或结果证据时，才允许这样概括。

## 不应该生成

- 普通主题或关键词；
- 正确建议；
- 单纯情绪；
- 没有明确错误对象的负面表达；
- 作者引用他人的观点但未表明认同；
- 仅凭外部知识推断出的错误；
- 与其他卡本质相同的重复错误；
- 原文没有问题、反转、结果或纠偏证据的候选；
- 只能依靠补充大量原文外事实才能成立的候选。

## 候选合并规则

- 错误对象、错误认知和错误场景基本相同时，合并为一张卡；
- 只是同一主题下的不同措辞，不重复生成；
- 如果错误发生阶段、行为主体或决策层级不同，且各自都通过五道门槛，可以分别保留；
- 合并后保留证据最完整、表达最清楚的候选。

## 场景规则

- 内部仍需理解错误发生的处境和行动；
- 最终不单独输出原文场景或场景来源；
- 将处境、错误、错误理由、问题结果和正确转向整合成一段连续口播稿；五个环节分别承担不同信息，不得用同义句重复误区观点；
- 写作时依次回答“在什么情况下、做错了什么、为什么会这么做、具体哪里不行、应该转向哪里”；
- 原文有对应表达的环节，优先保留原文核心词语、事实、人物处境、行为和判断，只做轻微改写、重组和口语化处理；
- 原文只有意思但没有完整句子的环节，可以根据原意重新组织表达；
- 原文缺少某个必要环节时，可以在原文核心方向上补写或创作人物、处境、数字、细节、结果和表达性结论；
- 创作内容必须服务于当前误区，不得改变原文核心方向、误区依据、人物行为、事实结果或纠偏逻辑；
- 创作内容不需要逐项由原文依据证明，但原文依据必须直接支持核心误区观点，不能被创作内容替代；
- 不得把创作内容写成原文、作者或受访者明确说过的事实；
- 不得出现“原稿里的老板”“源稿中的老板”“作者提到”“文中这个人”“受访者后来”等来源回指，也不得解释自己正在改写原文；
- 可以用“很多老板”“一个专业型老板”“你在做内容时”等泛化主体，不能保留原稿人物的追述结构；
- 创作内容必须服务于理解误区，不能喧宾夺主或凭空改变问题性质。

## 原文依据规则

本节只保留“依据必须直接支持误区”的原则。具体的认知证据、问题证据、纠偏证据、连续引文、段落范围和上下文完整性，统一以[误区观点与原文依据规则](viewpoint-and-evidence-rules.md)为准。

- 每张卡必须保留原文依据；
- 引句必须直接支持误区观点；
- 优先使用连续原文，不以关键词命中替代证据；
- 不单独输出场景来源说明。

## 标签规则

- 每张卡生成 1-3 个标签；
- 标签根据误区核心观点提炼；
- 不使用来源名、文件类型、处理状态、“误区卡”或“口播稿”等通用词；
- 标签要短、稳定、便于检索；
- 标签之间不得是同义重复。

## 三类分类规则

`category` 是一级内容分类，和 `tags` 不同。分类只能从以下三类中选择：

### `个人IP`

适用于个人 IP 内容生产和获客转化，包括短视频、直播、起号、选题、开头、内容表达、获客、引流、精准流量、内容变现、个人品牌、专家 IP 和账号运营。

判断重点：误区主要发生在“如何通过个人内容、账号或个人表达获得客户和结果”。

### `创业搞钱`

适用于创业、赚钱和商业经营，包括赚钱、财富、创业技巧、商业模式、产品价值、客户定位、企业管理、组织经营、交易、资源配置和经营结果。

判断重点：误区主要发生在“如何做生意、经营企业、获得收入或判断商业价值”。

### `成长逆袭`

适用于个人成长、能力提升和认知改变，包括执行力、能力提高、复盘、认知升级、沟通技巧、学习、习惯、心态、自我突破，以及从失败或低谷走向更好结果的个人成长。

判断重点：误区主要发生在“个人如何改变自己、提升能力、修正认知或突破当前状态”。

### 分类判断与留空

- 用户明确指定分类时，优先使用用户指定分类；
- 明确围绕账号、短视频、直播、IP获客时，归入 `个人IP`；
- 明确围绕创业、商业、赚钱、企业经营时，归入 `创业搞钱`；
- 明确围绕执行、能力、复盘、认知、沟通和个人突破时，归入 `成长逆袭`；
- 同时符合多个分类时，按误区主要发生的决策层级选择，而不是按标签数量选择；
- 个人成长只是 IP 或商业方法的附带结果时，仍按主要主题归入 `个人IP` 或 `创业搞钱`；
- 泛泛励志、无法确认具体分类时，写 `category: ""`；
- 不得创造第四类分类，也不得用分类名称代替具体 `tags`。

## 元数据规则

- 每张正式卡必须有 YAML frontmatter：`card_id`、`category`、`tags`、`source_address` 四个字段缺一不可；
- `card_id` 是全局唯一的独立编号，只存在于元数据，不进入一级标题；
- `category` 始终保留，只能使用 `个人IP`、`创业搞钱`、`成长逆袭` 或空字符串；具体边界按本文件“三类分类规则”执行；
- `tags` 使用 1-3 项 YAML 数组，标签不再写到一级标题；
- `source_address` 使用工作区相对路径，不写当前电脑的绝对路径；
- 一级标题只保留核心标题；默认文件名为 `<原文稿名>_<核心标题>.md`，编号不作为默认文件名组成部分；
- 正式落盘前检查编号唯一、分类字段存在、标签为数组、源地址相对化，以及标题与文件名一致。

## 全局去重规则

- 同一文稿内重复候选合并后，还必须与历史 `card-index.jsonl` 比较；
- 比较错误对象、错误动作、错误判断和错误发生阶段，不只比较标题或标签；
- 本质相同判为 `duplicate`，不生成新卡；主题相关但错误判断、对象或阶段不同判为 `related`，可以保留；无法判断判为 `uncertain` 并暂停；
- 不自动删除或覆盖历史卡片；
- 正式落盘前必须再次复核全局去重结果。

## 口播规则

- 使用连续段落，不拆成分行稿；
- 适合直接朗读，有真人表达感；
- 多用笃定语气，结合长短句；
- 不写成学术分析、原文摘要或逐字转录；
- 不机械重复误区观点；
- 让听者能够理解常见处境、错误做法、问题所在和正确转向。
- 原文有对应句子时，优先保留并轻微改写；原文只有意思时，基于原意重组；原文缺少必要环节时，允许合理补写。
- 可以使用合理创作增强真实感，但不冒充原文事实，也不歪曲原文。

## 落盘前质量门槛

- 候选卡必须先经过独立口语化润色，再接受独立审核；
- 审核确认误区、观点、标签、口播、原文依据、标题与文件名的一致性；
- 仅因口播包含合理创作细节不得退回；只有其与原文冲突、歪曲误区或冒充原文事实时才退回；
- 审核通过前不得将候选卡作为正式卡片写入输出目录。
