# 识别稿校正规则

## 目标

把 AI 语音识别稿或其他带文字噪声的原始稿，校正为可读、可定位、尽量忠实原意的 Markdown。校正不是润色，也不是重写。

## 可以直接修正

- 明显错别字和同音字；
- 根据上下文可以确定的专业名词、人名、数字和品牌名；
- 明显缺失或错误的句号、逗号、问号、冒号和引号；
- 连续语音被识别成一整段时的合理断句和分段；
- 文稿挤成一整段时，按语义重新划分段落；
- 明显重复的识别噪声；
- Markdown 标题、段落和表格的结构错误。

## 不得擅自修正

- 作者可能故意使用的口语、方言或不规范表达；
- 无法根据上下文确定的词；
- 作者的观点、立场、语气和论证顺序；
- 原文没有提供的事实、数字、案例或结论；
- 为了更好看而进行的文案改写。

## 语义分段规则

校正完成后，必须检查**整篇正文**是否存在大段连续文字、多个语义单元挤在同一段，或原有段落边界明显错误。若存在，必须在不改变原文顺序、观点、事实和语气的前提下，按语义重新分段。这里的“重新分段”不是摘要、缩写或口播改写，而是把同一份完整文稿重新排成可阅读的独立 Markdown 段落：

- 保留全文，不删除可分析内容；
- 每个段落围绕一个相对完整的语义单元展开；
- 段落之间使用 Markdown 空行明确分隔；
- 不能把全文继续保留为一整段，再声称已经完成段落优化；
- 如果原文已经合理分段，也必须检查并记录无需调整的结果。

具体分段依据包括：

- 新话题或新问题开始时分段；
- 错误做法、问题结果、解释理由和纠偏方向发生切换时分段；
- 案例、数字、引用或总结进入新的表达功能时分段；
- 不机械地一句一段，也不把同一论证拆成碎片；
- 不因分段新增事实、案例、结论或改写原文观点。

分段属于校正阶段，不属于后续口语化润色。它是进入误区识别前的必做动作，不得用“后面的口语化润色”代替。`transcription_normalization` 产物必须记录以下结构：

```json
{
  "paragraphReflow": {
    "changed": true,
    "beforeParagraphCount": 1,
    "afterParagraphCount": 4,
    "paragraphs": [
      {"paragraph": 1, "role": "提出问题", "boundary": "开头至问题提出"},
      {"paragraph": 2, "role": "错误做法", "boundary": "问题提出至错误做法结束"},
      {"paragraph": 3, "role": "问题结果", "boundary": "结果出现至解释开始"},
      {"paragraph": 4, "role": "纠偏方向", "boundary": "纠偏开始至全文结束"}
    ],
    "boundaries": [
      {"afterParagraph": 1, "reason": "新问题开始"},
      {"afterParagraph": 2, "reason": "问题结果转为解释"},
      {"afterParagraph": 3, "reason": "进入纠偏方向"}
    ]
  }
}
```

机器门禁会检查：字段是否完整、数量是否为非负整数、`afterParagraphCount` 是否等于校正稿实际语义段落数、`paragraphs` 是否逐段覆盖校正稿，以及 `boundaries` 是否与段落数量一致。`paragraphs` 只登记段落作用和边界，不复制或摘要正文。即使原稿已经分好段、无需改动，也必须记录 `changed: false`、实际前后段落数、完整段落清单和空边界数组。

## 不确定内容

无法确定时保留原词，不要猜测替换。必要时在处理结果中说明存在疑似识别问题，但不要用猜测内容污染校正稿。

## 元数据

保留原文件已有的 YAML frontmatter、来源字段、标题、链接和来源信息。校正流程可补充：

```yaml
transcription_normalized: true
normalization_scope: "错别字、断句、标点、明显识别错误、语义分段"
paragraph_reflow: true
```

## 边界

校正完成后，少走弯路只能使用校正后的文字；不得一边拆解一边继续凭推测修改来源内容。

对于 Excel 物化源稿，只允许校正 `## 全文` 下的作品文案。不得修改 YAML 中的 Excel 路径、工作表、物理行号、链接、标题和 `source_row_fingerprint`，也不得修改“来源字段”表格中的原始值。校正结果仍必须保存为同名 Markdown，并进入完整 V4 流程。

## V4 源文件写回门禁

校正和语义分段完成后，必须把完整校正后的 Markdown 原子写回原源文件，再启动误区候选识别。不能只把校正稿放在 `runs/<runId>/corrected.md` 中而继续使用未校正的源文件。产物必须记录：

```json
{
  "sourceWriteback": true,
  "sourceWritebackPath": "01_源知识库/视频文稿/示例.md",
  "sourceWritebackSha256": "由机器计算的源文件哈希"
}
```

机器门禁会重新计算源文件和 run 内 `corrected.md` 的哈希；二者不一致、路径不等于当前 `sourcePath`，或缺少写回证据时，不能进入候选识别。
