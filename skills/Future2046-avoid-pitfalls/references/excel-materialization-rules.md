# Excel 行级源稿物化规则

## 目的

Excel 只是源数据容器，不直接进入误区判断。每个包含“作品文案”列的非空数据行，先物化为一个 Markdown 源稿，再按现有 V4 流程逐篇处理。

## 支持格式

- 根据文件头自动识别 OOXML（`.xlsx`、`.xlsm`）和旧式 OLE `.xls`；
- 扩展名与实际格式不一致时，以文件内容为准；
- 文件损坏或解析依赖缺失时记录 `failed`，不生成伪造源稿。

## 工作表和列

扫描所有工作表，只处理存在文案列的工作表。文案列别名为：`作品文案`、`文案`、`作品内容`、`全文`。链接列别名为：`作品链接`、`选题链接`、`链接`、`视频链接`；标题列别名为：`作品标题`、`标题`、`选题`。

文案为空的行不生成文件，只记录 `empty_text`。文案非空但链接为空时仍生成文件，链接字段留空。完整文稿只保留在 `## 全文`，不在“来源字段”表格中重复；`作品文案`、`文案`、`作品内容`、`全文`及`全文摘要`等文稿/摘要字段从表格排除。其余来源字段全部保留在“来源字段”表格中。

## 文件名和来源元数据

文件生成在 Excel 所在目录，命名为：

```text
<Excel文件名>（连续编号）.md
```

编号以每个 Excel 为单位，从 1 开始；跨工作表按工作表顺序和物理行号递增。已经登记过的源行保持原文件名。文件冲突不得静默覆盖，必须记录 `conflict`。

每个物化文件必须保存：`source_type`、`source_excel`、`source_sheet`、`source_row`、`source_row_index`、`source_row_fingerprint`、`source_link`、`source_title` 和 `text_field`。卡片的 `source_address` 指向该 Markdown 的工作区相对路径。

## 指纹和幂等

行指纹由 Excel 相对路径、工作表名、物理行号和整行规范化 JSON 共同计算。指纹不变且目标文件存在时，状态为 `unchanged`，不重写；指纹变化时更新原 Markdown，并将它作为变化源稿重新送入完整 V4 流程；新增行生成新 Markdown。物化日志位于 `98_处理记录/excel-materialization-log.jsonl`。

## 与 V4 的关系

物化完成只代表源稿准备完成，不代表少走弯路流程完成。每个生成的 Markdown 必须依次通过 `source_scan`、校正、五道判定门槛、两次全局去重、独立口语化润色、独立审核、正式提交和最终校验。批量任务仍然严格一篇完成后才能开始下一篇。
