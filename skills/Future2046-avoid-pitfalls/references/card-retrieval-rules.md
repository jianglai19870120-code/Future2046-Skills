# 误区卡检索规则

## 适用场景

当用户不是要生成新卡，而是根据一个观点、问题、标签或内容主题寻找已有误区卡时，读取 `98_处理记录/card-index.jsonl`，不要重新扫描源文稿或重新生成卡片。默认只读取 `status: "active"` 的卡片；只有用户明确要求历史记录时，才返回 `superseded` 或 `archived`，并说明其生命周期状态和替代关系。

## 检索顺序

```text
用户查询
→ 检查索引存在、可解析且与卡片目录一致
→ 索引异常时从正式卡片重建
→ 匹配标题和误区观点
→ 匹配 tags 和 category；分类查询只使用 `个人IP`、`创业搞钱`、`成长逆袭` 三类，空分类单独处理
→ 匹配 errorObject、errorAction、errorStage
→ 分为高度匹配、相关卡片、弱相关卡片
→ 返回 card_id、标题、文件路径和匹配理由
```

## 匹配等级

- **高度匹配**：核心错误判断基本相同；
- **相关卡片**：主题或因果关系相关，但错误判断不同；
- **弱相关卡片**：只有分类或宽泛标签相同。

默认只展示高度匹配和相关卡片。用户要求扩大范围时，再展示弱相关卡片。

## 返回格式

```text
高度匹配：
MISC-000003-01｜把播放量当成真实获客结果
文件：02_误区卡片/把播放量当成真实获客结果_经纬 (2).md
匹配理由：错误判断都是把流量表现当成获客结果。
```

索引缺失或与卡片目录不一致时，先从正式卡片重建索引，再执行检索。

重建后必须重新校验 `card_id` 唯一、卡片路径存在、生命周期有效，以及索引元数据与 YAML frontmatter 一致。

索引使用 `cardId`，卡片 YAML 使用 `card_id`；检索结果对用户展示 `card_id`，不暴露内部字段命名差异。`relatedCardIds` 必须保持双向一致，除非相关卡片已经不是 active。
