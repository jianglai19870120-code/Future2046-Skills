# 分类避坑指南生成规则

## 触发时机

分类避坑指南不是单篇拆解的自动副产物。只有当前批次或用户明确指定的整组工作计划取得 `completed`，并且完成校验通过后，Skill 才在对话中询问是否生成指南。

询问由 Codex 对话层发出，不由脚本弹窗。分类名称从当前工作区 `workspace.yaml` 的 `supported_categories` 读取；当前通常包括：

- 新媒体
- 创业搞钱
- 成长逆袭

用户可以告诉 Skill 生成一个、多个或全部分类。多个分类必须按用户给出的顺序逐个生成、逐个审核和逐个落盘。

## 数据边界

生成器只读取：

- 工作区 `workspace.yaml`；
- `record_root/card-index.jsonl` 中 `status: active` 的索引记录；
- `card_root` 中与索引路径对应的正式 Markdown 卡片。

不读取 staging、失败 run、审核临时产物、归档卡片或重复历史文件。生成过程不得修改源稿、正式卡片、索引和历史运行记录。

## 篇章与小标签边界生成

分类指南不是把现有卡片的分类或 tags 反向整理成目录。生成某个分类的指南时，必须先由大模型完整阅读该分类的正式卡片标题和误区场景，判断这个分类整体覆盖的主题边界，再设计该分类专属的篇章和小标签。

边界方案必须包含每个篇章的定义、每个小标签的定义、纳入条件、排除条件、代表性卡片判断依据、当前正式卡片集合哈希，以及每张卡唯一的篇章、小标签和语义分配理由。

默认的起号篇、选题篇、文案篇、拍摄篇、剪辑篇、流量篇、用户篇、获客篇、直播篇和团队篇只作为候选边界。大模型可以根据当前分类的真实内容保留、合并或省略篇章和小标签，但不能为了凑数量创建空章节。

边界方案先经过 `review_category_boundary.py` 审核，审核通过后才能由 `generate_category_guide.py` 消费。生成器不得自行使用关键词推断篇章，也不得把单张卡片的 `tags` 当作可见小标签。无法证明唯一归属的卡片必须进入人工复核并停止当前分类。

## 交付文件

每个分类生成一个 Word 文件，文件名由分类变量决定：

```text
<分类>避坑指南.docx
```

文件写入 `workspace.yaml` 的 `guide_root`，当前为 `03_避坑指南`。生成草稿、边界方案、分配清单、审核报告、渲染图和哈希记录统一写入：

```text
<record_root>/guides/staging/<分类>/<guideRunId>/
<record_root>/guides/review/<分类>/<guideRunId>/
<record_root>/guides/render/<分类>/<guideRunId>/
<record_root>/guides/rollback/
<record_root>/cache/
```

首次生成使用 `<分类>避坑指南.docx`；同一分类已有正式版本时，使用 `<分类>避坑指南_YYYYMMDD_HHMMSS.docx`。审核失败时不得写入正式输出目录。

## 文档内容

文档只展示用户浏览所需的内容：

- 标题页；
- 分类索引；
- 按当前分类边界方案生成的篇章；
- 每个篇章下按当前边界方案划分的小标签；小标签来自大模型定义的语义边界，不从单张卡片的 tags 机械生成；
- 每张卡的编号、标题和误区场景。

不展示误区观点、错误后果、正确转向、原文依据、来源路径、卡片编号来源说明或机器审核字段。每个篇章编号从 1 开始，空篇章和空小标签省略；小标签直接显示语义名称，不添加“标签”“小标签”等字段前缀，也不改变卡片原有 tags。

小标签的固定边界为：起号篇下的账号定位、人设、差异化、个人品牌基础；选题篇下的选题方向、内容策略、受众与主题匹配；文案篇下的标题、开头、脚本、表达、结构、语言；拍摄篇下的镜头、画面、构图、出镜、场景；剪辑篇下的剪辑、字幕、节奏、特效、后期制作；流量篇下的平台分发、播放量、推荐、涨粉、热点、发布频率；用户篇下的用户理解、注意力、信任、互动、需求心理；获客篇下的产品、人群、痛点、成交、转化、商业结果；直播篇下的直播间、直播表达、直播运营、直播成交；团队篇下的团队分工、交付、老板角色、管理、协作。

## 统一版式契约

分类指南使用以下固定视觉层级；分类名称必须由当前 `category` 动态替换，不得把“新媒体”写死：

- 封面标题为单行 `<分类>避坑指南`，Microsoft YaHei、56pt、红色 `#D20000`、加粗；保留标题下方的蓝色规则线。
- 封面副标题为“把复杂的<分类>行业误区，整理成可以快速浏览的判断地图”，Microsoft YaHei、14pt、灰色 `#5F5F5F`。
- 封面品牌为“@姜来已来2046”，Microsoft YaHei、12pt、红色 `#D20000`、加粗；通过封面间距保持在标题区下方的固定位置。
- 目录篇章名称和数量统一使用深红色 `#C00000`；篇章名称加粗，数量保持常规字重。
- 正文篇章标题使用红色 `#D20000`、24pt、加粗；正文小标签使用深红色 `#C00000`、13pt、加粗。
- 卡片标题和误区场景正文继续使用黑色层级，不跟随小标签改色；正文段落间距、行距和分页规则保持现有生成器设置。

版式同步以最终渲染效果为准，不依赖 Word 内部自动生成的样式编号。修改生成器后必须重新渲染封面、目录和正文页面，并执行跨分类回归，确认动态分类名称和版式均正常。

篇章名称由当前分类的边界方案决定。若正式卡片无法可靠归入任何篇章或小标签，不生成该分类的正式指南，保留人工复核清单。

## 审核门禁

每个分类都必须先独立审核边界方案，再独立审核 Word 指南。边界审核至少检查：篇章定义、小标签定义、边界重叠、空标签、卡片集合覆盖和逐卡唯一 assignment。指南审核至少检查：分类筛选、卡片数量、卡片来源、重复卡片、篇章归属、篇章编号、标题与场景原文、Word 可打开性、中文字体、分页、长文本溢出和版式一致性。

审核报告必须记录输入卡片哈希、输出 Word 哈希、纳入数量、篇章数量、结构审核结论、视觉审核状态和失败原因。没有 LibreOffice 或没有逐页检查 PNG 时，`visualReview` 必须保持 `pending`；只有结构审核为 `pass` 且 `visualReview: pass` 才能执行正式替换。

## 对话协议

批次完成后，使用以下询问：

```text
本批次已完成。是否生成分类避坑指南？

可选择：
- 新媒体避坑指南
- 创业搞钱避坑指南
- 成长逆袭避坑指南

请告诉我需要生成哪几个。
```

用户未选择时不生成；用户选择后逐个执行。单篇完成、暂停、失败或校验未通过时不显示该询问。
