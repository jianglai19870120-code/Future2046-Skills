# 执行效率规则

## 目的

本文件只优化执行方式，不降低误区识别、口播润色、独立审核、全局去重和串行落盘的质量要求。

Skill 保留 14 个 V4 逻辑阶段作为审计契约，但不要求每个阶段都由一次独立的人工操作、一次独立的进程或一次完整上下文传递完成。

## 六个质量节点

实际执行按以下六个节点组织：

```text
1. 校正与分段
2. 候选识别与五道门槛
3. 文内合并与首次全局去重
4. 初稿生成与强口播润色
5. 整篇独立审核
6. 最终去重、提交与完成校验
```

每个质量节点内部仍必须产生对应的 V4 阶段产物和回执。合并节点只是减少重复启动和重复读取，不得删除阶段证据。

## 可以合并的工作

- `source_scan` 和 `transcription_normalization`：一次读取源稿，完成快照、校正、分段和写回。
- `misconception_candidate_identification` 和 `five_gate_judgment`：先穷举候选，再在同一结构化结果中逐候选完成五道门槛。
- `intra_document_deduplication` 和 `global_deduplication_pre`：先做文内合并，再读取一次索引完成首次全局比较。
- `card_draft_generation` 和 `oral_polish`：同一篇中先生成 draft，再对每张卡独立生成 polished；不得把 draft 直接当成 polished。
- `formal_card_write`、`index_update`、`processing_log_write` 和 `completion_validation`：由一次可恢复提交统一完成，但仍分别写入回执。

## 不得合并或取消的质量门禁

- 不能取消校正和语义分段；
- 不能把候选识别和五道门槛变成发现一条就立即落盘；
- 不能取消文内去重和两次全局去重；
- 不能取消强口播润色；
- 不能用生成者自审代替独立审核；
- 不能在当前篇正式提交、索引更新、日志写入和最终校验前启动下一篇。

## 独立审核的效率规则

默认按“一篇源稿一次审核调用”组织审核请求，一次提交该篇全部候选卡，而不是每张卡单独调用审核器。

审核输入只包含：

- 校正稿中与候选对应的连续证据段；
- 候选、五道门槛和文内去重结果；
- draft 与 polished 卡片；
- 首次全局去重的相似卡摘要；
- 元数据和文件名。

不重复发送整个工作区、全部历史卡片正文或无关源稿。

审核结果仍必须逐卡给出 `approved` 或 `rejected`。只有被拒绝的卡进入修订；已通过的卡不重复润色和审核。

## 全局去重的效率规则

全局去重先使用索引字段做粗筛，只把最相近的少量历史卡送入语义复核：

```text
分类、标签、标题和观点关键词
→ 错误对象、动作、判断和阶段
→ 最相近的历史卡语义复核
```

粗筛只用于缩小范围，不能直接判定重复。默认只复核最相近的 3—10 张卡；如果候选证据显示相似范围更大，必须扩展范围，不能为了提速截断比较。

## 单篇执行约束

同一篇仍然是一个独立 run，所有质量节点按顺序执行。效率优化只减少重复读取、重复进程和重复上下文，不改变单篇串行和批次锁。

## 失败处理

任一质量节点失败，保留当前已生成的真实产物和阶段回执；不得为了提速伪造后续阶段。审核失败只修订被拒绝卡片，重新执行从 `oral_polish` 到 `independent_review` 的必要链路；索引变化时必须重新执行最终全局去重。
