# Skill 制作器

## 目标

把反复出现的能力需求沉淀为边界清楚、可以安装、可以测试、可以回退的 Future2046 Skill。先确认问题和交付，再修改文件；不能把一次性答案或单个案例硬编码成长期规则。

## 工作路线

根据任务选择一条路线：

1. **新建或大改**：读取现有仓库结构、相关 Skill、资源和测试，形成问题契约、文件结构、行为规则、验证计划和回退方案，等待用户确认后写入。
2. **改进已有 Skill**：先取得失败案例或反馈，定位偏离发生的步骤，区分规则、方法和流程骨架问题，用同一组任务比较修改前后结果。
3. **小范围修改**：明确目标文件、具体行为、不改内容和回退点；确认后修改并执行结构校验。
4. **只读诊断与测试**：只报告结构、引用、版本、测试和发布范围问题，不擅自写入。
5. **版本与发布**：检查版本、注册表、路由目录、安装副本和公开范围；远程仓库、commit、push、tag 或 Release 必须在用户明确授权后执行。

## 不变量

- 先方案，后写入；
- 写入前保护用户已有改动，并保留可回退点；
- 只修改明确授权的文件和范围；
- 不把真实工作区、源稿、卡片、运行记录、密钥或本机路径写入公开包；
- 新增或修改 Skill 后同步更新元数据、注册表、路由目录、版本和安装副本；
- 结构校验只能证明结构正确，真实任务测试才能证明行为有效；
- 未实际运行的测试不得宣称通过。

## 标准流程

```text
读取现场
→ 明确问题契约
→ 选择改动路线
→ 形成方案并等待确认
→ 创建快照或确认 Git 回退点
→ 修改 Skill 与直接引用资源
→ 运行结构和行为校验
→ 同步版本、注册表、路由和安装副本
→ 检查公开发布范围
→ 构建并验证发布包
```

## 发布边界

发布前必须检查仓库状态、远程目标、分支、暂存范围、密钥、个人路径、工作区数据和隐藏缓存。只使用明确文件路径暂存，禁止把整个工作区无差别加入提交。没有明确的仓库所有者、仓库名和可见性时，停在本地准备阶段。
