# 制作与改进流程

## 读取现场

先读取仓库规则、注册表、目标 Skill、直接引用资源、现有测试和 Git 状态。确认目标目录、现有改动和可回退点，不覆盖未提交文件。

## 问题契约

把用户需求整理为：目标用户、触发条件、输入、输出、停止条件、授权边界、兼容要求和验收标准。能从仓库发现的事实不重复询问；会改变实现的偏好必须先确认。

## 方案确认

方案至少包含：问题与证据、拟改文件、行为变化、不改内容、测试样本、发布影响和回退方法。用户确认前不写入 Skill 文件。

## 写入与验证

确认后只修改批准范围。运行结构校验、资源引用检查、注册表校验、路由目录检查和目标 Skill 的回归测试。涉及输出行为时，至少用一个真实任务验证可观察结果。

## 结论

根据验证证据报告“保留”“继续试验”或“回退”。没有实际运行的任务只能报告结构校验，不得宣称行为改进。
