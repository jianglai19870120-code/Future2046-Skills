# 逐题语义审核规范

这份规范是每一条作品审核时的执行模板。八大元素词典回答“元素是什么”，本规范回答“如何把一条标题审成可落盘的词根关系”。

## 一条标题的完整审核卡

```json
{
  "title": "清理话题后的完整标题",
  "analysis": {
    "semantic_summary": "只概括标题明确表达的对象、行为、关系、结果或场景",
    "element_checks": [
      {
        "element": "人群",
        "applicable": false,
        "reason": "标题没有明确身份、条件或共同处境"
      }
    ],
    "candidate_summary": "说明为什么提出这些词根；没有词根时说明排除原因"
  },
  "decisions": [
    {
      "root": "标准爆款词根",
      "element": "元素名",
      "status": "approved",
      "derivation": "说明标准词根如何由标题证据片段组合或压缩而来",
      "rationale": "说明该标题为什么符合元素定义",
      "evidence": ["标题中的逐字片段"],
      "auditor": "独立复核 AI",
      "audit_checks": {
        "root_faithful": true,
        "evidence_exact": true,
        "element_valid": true,
        "reason_supported": true
      },
      "audit_reason": "独立说明词根忠实于标题、证据逐字存在且元素成立"
    }
  ]
}
```

## 审核顺序

### 1. 先读完整语义

不能先看到某个词就直接归类。先回答：标题在说谁、什么对象、什么行为、什么关系、什么结果或什么场景？只记录标题明示或由语法直接推出的内容。

### 2. 八类全部过一遍

每条标题都必须有 8 个 `element_checks`，不能只记录命中的元素。`applicable: false` 时必须写排除理由，例如“只有收益结果，没有投入或门槛，因此不成立成本”。

### 3. 再提炼标准词根

标准词根不是任意关键词，也不是整条标题。它应当是可被复用的最小语义单元：

- 可以把多个标题片段组合成一个词根；
- 可以做必要的语法补全；
- 不得增加标题没有表达的身份、对象、关系、结果或外部事实；
- `derivation` 必须逐一说明证据片段如何形成词根。

### 4. 审核证据闭合

证据数组必须非空，每个片段必须逐字出现在清理后的标题中，并且确实支撑词根。标题中出现但与词根无关的数字、地点、人物名不能滥列为证据。

### 5. 独立复核四项

独立复核必须明确回答：

1. `root_faithful`：标准词根是否忠实于标题语义；
2. `evidence_exact`：证据是否逐字来自标题；
3. `element_valid`：元素定义是否适用；
4. `reason_supported`：提炼理由和归类理由是否被标题支持。

四项不能全部为 `true` 时，关系只能 `rejected` 或 `uncertain`，不得进入正式词典和热度汇总。

## 无词根标题

无词根不是空白记录。必须保留完整语义概括、8 类排查结果和 `candidate_summary`，说明为什么没有任何元素达到命中门槛。只有这样，后续标题变化时才能区分“已经审核且无词根”和“尚未审核”。

## 禁止的快捷判断

- 词根出现在历史词典中，不代表当前标题自动命中；
- 标题出现“最、竟然、反而、赚钱、答案”等提示词，不代表自动属于某元素；
- 已知人物的职业、身份或背景不能从外部常识补入标题；
- 证据片段出现在标题中，不代表它自动是有效证据；
- 旧版只有单字符串 `evidence` 的审核记录不得复用。

## “最差”的硬门槛

“最差”只接受严格白名单中的直接极端表达：`最坏`、`最差`、`最难吃`、`最难喝`、`最难用`、`最不好`、`最不好的`、`最垃圾`、`最失败`、`最糟`、`最糟糕`、`最黑暗`、`极差`、`极烂`、`一文不值`。

审核通过前必须同时满足：

1. `worst_trigger` 完整等于白名单中的一个词；
2. `worst_trigger` 逐字出现在清理后的标题中；
3. `worst_trigger` 同时列入 `evidence`；
4. `worst_basis` 固定为 `极端体验`。

`四不像`、`不好用`、`没人看`、`没流量`、`被淘汰`、`失败`、`死局`、`下策`、`流量低`、`垃圾`、`最傻`、`毁掉`、`错误`、`误区`、`问题`、`风险`、`困难`、`坑`等，即使具有负面含义，也不得通过解释升级为最差。旧审核记录如果不满足白名单和字段要求，必须重新审核。

“最差”关系的审核字段示例：

```json
{
  "element": "最差",
  "worst_basis": "极端体验",
  "worst_trigger": "最垃圾",
  "evidence": ["最垃圾", "IP获客"]
}
```
