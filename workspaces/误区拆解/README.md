# 误区拆解工作区

## 这是什么

这是用于保存行业资料、误区卡片和处理记录的个人工作区，不是 Skill 安装包。

你可以把它用于餐饮、教育、咨询、短视频、创业服务或其他任何行业，持续收集高质量资料，识别行业中常见的坑和错误认知，帮助自己提前避坑、少走弯路。

Skill 的能力和业务规则保存在单独的 Skill 包中；这个工作区只保存你的输入资料、生成结果和运行状态。

## 这个工作区能做什么

工作区支持以下使用方式：

- 导入一篇文章、书籍、访谈、视频文稿或新闻稿；
- 持续导入同一行业的多种资料；
- 导入包含“作品文案”列的 Excel，按行生成源稿；
- 逐篇识别有原文依据的错误认知、错误做法和行业陷阱；
- 保存经过审核的误区卡，作为后续行业避坑和观点调用的内容资产。

## 目录结构

```text
误区拆解工作区/
├── workspace.yaml
├── 01_源知识库/
├── 02_误区卡片/
├── 98_处理记录/
└── 99_归档/
```

| 目录或文件 | 用途 |
|---|---|
| `workspace.yaml` | 工作区配置入口，定义各类资料和结果的目录位置 |
| `01_源知识库` | 文章、书籍、访谈、视频文稿、新闻稿、TXT、Markdown、DOCX、PDF 和 Excel |
| `02_误区卡片` | 经过完整流程和审核后正式落盘的误区卡 |
| `98_处理记录` | V4 阶段产物、索引、日志、审核证据和恢复状态 |
| `99_归档` | 用户明确归档的历史资料 |

## 如何开始使用

```text
复制工作区模板
→ 可以修改工作区外层文件夹名称
→ 将源资料放入 01_源知识库
→ 把工作区路径提供给 Codex
→ 调用 $future2046-avoid-pitfalls
→ 确认处理范围
→ 等待文稿逐篇处理
→ 在 02_误区卡片 查看正式结果
```

调用时提供工作区根目录，例如：

```text
$future2046-avoid-pitfalls
请读取这个工作区：E:\我的行业避坑库
按源文件顺序处理尚未完成的文稿。
```

不能只把 `01_源知识库` 子目录单独提供给 Skill。必须提供包含 `workspace.yaml` 的工作区根目录。

## 支持的源文件

可以把以下资料放进 `01_源知识库`：

- `.md`、`.txt`；
- `.docx`、`.pdf`；
- `.xlsx`、`.xls`、`.xlsm`；
- 书籍、文章、访谈、视频文稿、新闻稿等已经整理成文字的内容。

Skill 会先扫描源知识库，再根据你的确认处理新增或变化的源稿。没有明确指定文件时，通常会先展示待处理清单，不会直接覆盖源文件或生成正式卡片。

## Excel 文稿如何进入流程

Excel 不会直接进入误区识别。Skill 会先读取包含“作品文案”列的工作表，按行生成独立 Markdown 源稿，再让每个 Markdown 源稿进入完整流程。

- 原始 Excel 保留不动；
- 生成的 Markdown 位于源知识库目录；
- Excel 生成的 Markdown 仍然需要校正错别字、标点、断句和语义段落；
- Excel 行级物化只代表源稿准备完成，不代表误区卡已经生成；
- 具体列名、指纹、变化检测和命名规则由 Skill 包内的 Excel 规则负责。

## 完整生产流程

工作区层面看到的生产链路是：

```text
扫描源文件
→ 必要时物化 Excel 行文稿
→ 校正文字并重新划分语义段落
→ 识别有依据的误区候选
→ 生成、润色并审核卡片
→ 正式写入 02_误区卡片
→ 更新 98_处理记录
```

每篇文稿必须依次完成。当前文稿取得合法终态、正式结果和处理记录后，才能开始下一篇。

误区识别门槛、口语化场景标准、独立审核、全局去重、V4 阶段产物和恢复方式不在工作区 README 中重复定义，统一以 Skill 包内的 `SKILL.md` 和参考规则为准。

## 输出卡片说明

正式卡片保存在：

```text
02_误区卡片
```

卡片通常包含：

- YAML 元数据；
- 独立编号、分类和标签；
- 原文稿的工作区相对地址；
- 不超过 24 个汉字的误区观点；
- 口语化、适合朗读的误区场景；
- 直接支撑观点的原文依据。

卡片文件只在完整流程通过并正式提交后写入输出目录。不要直接手动修改正式卡片、索引或处理中间文件；需要重跑时，应通过 Skill 的授权流程处理。

## 处理记录与恢复

```text
98_处理记录
```

用于保存：

- 源稿扫描和队列信息；
- Excel 行级物化记录；
- V4 各阶段产物和哈希；
- 独立审核证据；
- 卡片索引和处理日志；
- 中断后的提交清单和恢复状态。

如果处理过程中断，不要直接删除锁、运行目录或处理记录，也不要手动把状态改成 `completed`。应把当前工作区路径和错误信息交给 Skill，先恢复或处理当前文稿，再继续后续队列。

## 工作区改名和迁移

Skill 不识别外层文件夹名称，而是读取工作区根目录的 `workspace.yaml`。因此可以自由修改工作区名称、所在盘符和所在位置。

例如以下名称都可以使用：

```text
E:\我的行业避坑库
D:\餐饮研究资料
C:\Users\用户名\Documents\教育行业知识库
```

### 可以修改

- 工作区外层文件夹名称；
- 工作区所在盘符；
- 工作区所在位置。

### 默认不要修改

```yaml
source_root: "01_源知识库"
card_root: "02_误区卡片"
record_root: "98_处理记录"
archive_root: "99_归档"
```

如果确实要修改这四个目录名称，必须同步修改工作区根目录的 `workspace.yaml`。Skill 会按配置读取目录，不依赖默认中文目录名，但不能只改文件夹而不改配置。

### 必须保留

工作区根目录必须保留：

```text
workspace.yaml
```

不要只复制 `01_源知识库`，也不要把工作区中的真实资料复制进 Skill 安装目录。

## 分享和隐私边界

工作区包含个人资料和生产结果，默认不属于公开发布内容。

- 可以分享空白模板；
- 不要上传真实源稿、Excel、误区卡片、索引、日志、审核证据或运行状态；
- 原始 Excel 和个人知识库应留在自己的工作区；
- 对外分享 Skill 时，只分享 Skill 包和空白工作区模板；
- 迁移到新电脑时，可以复制整个工作区，但应先确认其中资料的版权和隐私边界。

## 常见问题

### 改了工作区文件夹名称后，Skill 会找不到吗？

不会。只要提供包含 `workspace.yaml` 的工作区根目录，外层文件夹可以任意命名。

### 可以修改四个中文目录名吗？

可以，但必须同步修改 `workspace.yaml` 中对应的路径字段。最稳妥的方式是保留默认目录名。

### Excel 已经生成 Markdown，为什么还没有误区卡？

Excel 行级物化只是把表格内容变成可处理的源稿。每个 Markdown 仍需要经过校正、误区判断、去重、口语化润色、独立审核和正式落盘。

### 为什么不能直接把卡片放进输出目录？

因为正式卡片必须绑定当前源稿、审核结果、去重结果和处理记录。直接复制文件会破坏 V4 生产证据和索引一致性。

### 下载后应该把整个模板复制到哪里？

复制到任意你方便管理的位置即可，例如 `Documents`、E 盘或项目资料目录。复制完成后，把新工作区的完整路径告诉 Codex。
